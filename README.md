# ldry-scrtry (정부24 길잡이, 비공식)

정부24에서 **다음에 누를 곳**을 빨간 테두리로 알려 주는 **실험용** 크롬 확장이다.
가정한 상황: 어르신이 정부24에서 서류(예: **주민등록표 초본**)를 떼려는데 정확한 서류 이름도, 어디를 눌러야 할지도 모른다.

- 해커톤 본 결과물(배포 웹 서비스)과 별개다. **크롬 웹스토어 공개 배포가 목표**다 (`../docs/requirementSpec.md` D-7). 웹스토어에 제출해 **심사 중**(2026-10-17)이고, 로컬 로드로도 쓸 수 있다. 배포 현황·Railway 중계·남은 일은 `AGENTS.md`에 있다.
- 화면 이름은 "민원 길잡이 (비공식)"이다 (노인 UX 규칙: 화면에 영어를 쓰지 않음). 확장 목록에는 `ldry-scrtry`로 보인다 (D-8. 이전 이름 GVRNMNT24 detector). 정부24·행정안전부와 관계없는 비공식 도구다.
- 직접 누르거나 입력하지 않는다. 알려 주기만 한다.

## 동작

**1. 무엇을 찾는지 고르기 (검색 → 선택)**
- 어르신이 쉬운 말로 적거나 「말로 하기」로 말한다 (예: "이사 다닌 기록이 나오는 서류").
- Jev가 **정해진 민원 목록**(`src/lib/catalog.js`, 27개: 정부24 "자주 찾는 서비스" + 등본·초본 분리 + 기관 사이트로 넘어가는 서류 + 가족관계 증명서 5종) 중에서 가까운 것을 확률 순으로 최대 4개 고른다. 각 항목에는 쉬운 설명이 붙는다. 어르신이 그중 하나를 누르면 그것이 목표가 된다.
- **적은 말은 목표 문장에 들어가지 않는다.** 안내에 쓰는 목표는 고른 목록 항목의 이름·설명으로만 만든다 (`goalFor`). 적은 말은 목록 검색에만 한 번 쓰인다.
- 이름·번호처럼 보이는 말은 보내지 않고 "개인정보는 적지 말아 주세요"를 띄운다. 중계 서버가 안 되면 이 컴퓨터에서 글자 맞추기 검색으로 대신한다. 「목록에서 직접 고르기」도 있다.

**2. 다음에 누를 곳 안내**

```
content.js (정부24 화면)                     background.js (신뢰 영역)               TypeSafe
 보이는 버튼·링크·선택지·입력 칸 이름 모으기 ──▶  개인정보 거르기 → 캐시 확인 ──▶  Jev Choice 2개
 (값은 안 읽음, "채워졌는지"만)                  → 중계 서버(Railway) → 키는 서버에만   nextControl: 다음에 쓸 것
 빨간 테두리 + 안내 창 그리기          ◀──      정책: 확률 ≥ 0.35 이면 가리킴 ◀──  pageStage: 지금 단계
```

- **생성 대신 선택:** 코드가 후보 이름을 모으고 Jev는 그중 하나를 고른다. 없는 버튼을 지어낼 수 없다. 항상 "해당 없음" 선택지를 넣는다.
- **보내는 것:** 목표 문장, 화면 제목, 주소(호스트+경로, 쿼리 없음), 제목 글(h1~h3, 5개), 버튼·칸 이름, 앞서 누른 이름(8개). 숫자 6개 이상·이메일·"○○님"이 들어간 글자는 통째로 버린다 (`src/lib/sanitize.js`).
- **고른 후보의 확률이 0.35 미만이거나 "해당 없음"이면** 테두리를 그리지 않고 "가족이나 정부24 고객센터에 물어봐 주세요"를 띄운다 (`MIN_PROBABILITY`, `src/lib/jev.js`). confidence가 아니라 확률을 쓰는 이유: 맞는 길이 둘(회원·비회원 신청)이면 confidence가 0.2대로 떨어진다.
- **떠 있는 창:** "발급하기"를 누르면 뜨는 "회원/비회원 신청하기" 창처럼 `role="dialog"`가 없는 창도 찾는다. 창이 떠 있으면 **창 안의 후보만** 보내고, 창의 안내 글(`popupText`, 160자)을 함께 보낸다.
- **약관 동의: 「필수」만 표시한다.** 규칙이 분명해 Jev에 묻지 않고 코드가 정한다 (`consentKind`, `src/content.js`).
  - 체크 안 된 「필수」 동의 칸을 **모두 한 번에** 테두리로 표시하고, "「선택」 동의는 체크하지 않아도 돼요"라고 알린다.
  - 「선택」 동의, 「전체 동의」(선택까지 동의됨), 「동의하지 않음」은 후보에서 **아예 뺀다** → Jev도 고를 수 없다.
  - 필수를 다 체크하면 그때 Jev에 다음 버튼(「다음」·「확인」 등)을 묻는다.
  - 판단 근거: 칸 이름이나 가까운 줄(6단계 위, 400자 이하)에 있는 `[필수]`·`(필수)`·`필수 동의` / `[선택]`·`(선택)`·`선택 동의` 표시. 둘 다 있거나 둘 다 없으면 손대지 않고 Jev에 맡긴다. **실제 정부24 약관 화면의 표기는 아직 확인 못 했다** (시험은 가짜 화면 `test/fixtures/consent.html`).
- **안 보이는 버튼은 후보에서 뺀다:** 옆으로 넘기는 목록의 다른 장, 접힌 메뉴 안의 버튼(조상이 `overflow: hidden`으로 잘라 낸 것)은 가리킬 수 없으므로 보내지 않는다.
- **안내 창 자리:** 기본은 오른쪽 아래. **지금 자리에서 테두리를 가릴 때만** 반대쪽으로 옮기고, 그 밖에는 움직이지 않는다 (`avoidCovering`).
- **묻지 않는 화면:** 접속 대기 화면, 접속 차단 화면.
- **로그인은 사용자가 직접 (D-10):** 로그인·회원가입·인증 방법·회원/비회원 버튼은 후보에서 빼서 AI가 "로그인부터"를 고를 수 없다. 로그인 방법(인증서·간편인증·모바일 신분증·아이디·비회원)이 둘 이상 보이거나 회원/비회원 선택 창이 뜨면 **테두리를 끄고** "여기서부터는 직접 골라 주세요"만 보여 주며 서버에 묻지 않는다 (`src/lib/handoff.js`, 모든 사이트 공통). 서류 페이지로 가는 길(링크, 또는 사이트 검색 칸 — 서류 이름을 적으라고 알림)을 먼저 안내한다.
- **신청서의 고르는 칸은 사용자가 직접 (D-11):** 「본인·가족」「일반·상세·특정 증명서」처럼 사람마다 답이 다른 고르는 칸은 후보에서 뺀다. 서류 종류 칸(예: 「초본」, 「혼인관계증명서」)과 약관 동의만 남는다. 신청서 화면이면 위쪽 줄에 "「본인」·「가족」 같은 고르는 칸은 직접 골라 주세요"를 쓰고, 다음 버튼을 가리킨다. 이미 그 서류 화면인데 같은 이름의 메뉴 링크가 있으면(본인 확인 뒤) 그 링크는 뺀다 — 다시 누르면 처음으로 돌아가 본인 확인이 풀린다 (`src/lib/handoff.js`).
- **다시 묻는 때:** 화면이 열릴 때, 누른 뒤, 선택·입력이 바뀐 뒤, 화면이 바뀌어 가리키던 곳이 사라졌을 때. 같은 화면·같은 기록이면 캐시(30분)로 답한다.

## 길잡이가 뜨는 사이트 (정부24 + 넘어갈 수 있는 기관 사이트)

정부24 민원 중에는 다른 기관 사이트에서 발급하는 서류가 있다. **길잡이는 정부24와 아래 기관 사이트 12곳에서 켜진다 (D-9).** 서류를 고르면 목표에 "이 서류는 ○○ 사이트에서 발급되고 정부24가 그리로 보낼 수 있다"가 들어가, 넘어간 뒤에도 안내가 이어진다. **정부24 밖 사이트는 화면 속 글(제목 글·창 안내 글)을 서버로 보내지 않는다.** 끄려면 `src/lib/sites.js`에서 `active`를 지우고 `manifest.json`을 맞춘다.

- 민원 목록(`catalog.js`)에는 이 공지의 서류와 가족관계 증명서 5종을 더해 27개다. 정부24 민원은 약 5,000종이라 목록에 없는 것은 "아직 길잡이 목록에 없어요"로 안내한다.

## 설치 (로컬 로드)

1. `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램 로드** → 이 폴더(`gvrnmnt24-detector/`) 선택 (빌드 단계 없음)
3. (선택) 툴바의 확장 아이콘 → 설정 창에서 **연결 확인** → "연결됐어요." (키는 없다. 서버가 잠들어 있으면 두 번 눌러야 할 수 있다)
4. 정부24(`www.gov.kr` 또는 `plus.gov.kr`)를 열면 오른쪽 아래에 길잡이 창이 뜬다 → 처음에는 **동의 화면**이 나온다 → 동의한 뒤 떼고 싶은 것을 쉬운 말로 적고 「찾기」 → 나온 목록에서 고르기

코드를 고친 뒤: 확장 카드의 **새로고침** → 정부24 탭 **새로고침**.

## 명령어 (의존성 없음, Node 22 이상)

| 목적 | 명령 |
|---|---|
| 검사 (커밋 전) | `npm run check` = 문법·매니페스트·권한·외부 스크립트·키 흔적 검사 + 단위 시험 |
| 단위 시험만 | `npm test` |
| 연기 시험 (실제 정부24 + 가짜 Jev) | `npm run smoke` → `smoke-out/` (화면 사진, 보낸 요청, summary.json) |
| Jev 정답률 시험 (실제 호출, 비용) | `TYPESAFE_API_KEY=... npm run trial` → `trial-out/` |
| 배포용 zip | `npm run package` → `ldry-scrtry.zip` (`manifest.json`·`src`만. 서버 코드는 안 들어감) |
| 중계 서버 로컬 실행 | `TYPESAFE_API_KEY=… PORT=8788 npm start` (계약: `server/openapi.yaml`) |

- `smoke`는 Playwright를 새로 설치하지 않고 `../slop-detector/node_modules`의 것을 빌려 쓴다. 다른 곳의 것을 쓰려면 `PLAYWRIGHT_FROM=<package.json 경로>`.
- `plus.gov.kr`(메인·로그인)은 자동화 브라우저를 "서비스 접속이 차단되었습니다"로 막는다. **우회하지 않는다.** 그래서 `smoke`는 `www.gov.kr` 구간만 자동으로 확인하고, 메인·로그인은 사람이 실제 크롬에서 확인한다.
- `trial`은 두 가지를 잰다 (`MODE=pages|search`로 하나만 가능).
  - 다음 버튼: `test/fixtures/pages.json`의 화면 4개(메인, 민원안내, 회원·비회원 창, 로그인)를 후보 순서를 바꿔 3번씩 (12회). 로그인 화면은 자동화가 막혀 HTML에서 버튼 이름을 재구성했다.
  - 민원 찾기: `test/fixtures/search.json`의 쉬운 말 15개 → 1순위가 맞는지, 보여 주는 후보 안에 있는지 (15회).
