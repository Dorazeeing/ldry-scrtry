## 1. 목표

[rbilgil/slop-detector](https://github.com/rbilgil/slop-detector)(MIT)를 포크해서, X 피드 게시물을 **Jev(TypeSafe) 판정**으로 가려 주는 **한국어 크롬 확장**을 만들고, **실험 등록**(로컬 로드, 선택적으로 웹스토어 Private)까지 확인한다.

## 2. 범위

| 포함 | 비목표 (하지 않음) |
|---|---|
| X(`x.com`) 피드 게시물·답글의 **글자** 판정 | 사진·영상·링크된 기사 판정 |
| Jev 질문 4개(신호별)로 판정, 코드가 정한 기준으로 가리기 | GPTZero 판정, Cloudflare 중계 서버(`proxy/`) |
| 한국어 화면(설정 창, 라벨, 가림 막대) | 휴대폰 지원 (휴대폰 크롬은 확장 미지원) |
| 사용자가 **자기 TypeSafe 키**를 넣는 방식(BYOK) | 우리 키를 확장에 넣어 배포 |
| 로컬 로드 실험, (선택) 웹스토어 **Private + 지정 테스터** | 웹스토어 Public·Unlisted 등록, 유료화 |
| 한국어 정확도 시험 스크립트 | "더 보기"로 접힌 뒷부분 가져오기 |
| | 정부24 길잡이 (별도 확장 = 이 저장소 루트, D-6) |

## 3. 기능 요구사항

| ID | 요구사항 | 근거·참고 |
|---|---|---|
| **FR-1 게시물 찾기** | X 피드의 게시물·답글을 원본 방식대로 찾는다: 선택자 `article[data-testid="tweet"]`, 본문 `[data-testid="tweetText"]`, ID는 `/status/숫자`. 화면에 0.25초 이상 보인 게시물만, 동시에 최대 3개까지 판정을 요청한다. 같은 게시물은 한 번만 판정한다. | 원본 `extract.ts`, `content.ts` `pump()` |
| **FR-2 Jev 판정** | `POST https://api.typesafe.ai/v1/systemone`을 **직접** 호출한다(`ai` SDK의 `experimental_evaluate`를 거치지 않음). `model`은 `jev-latest`. 한 요청에 Noul 질문 4개를 보낸다: `aiGenerated`, `engagementBait`, `hiddenAd`, `scamSignal` (문구 초안은 `usePlan.md` §3-3). | `usePlan.md` §3-1, §3-3 |
| **FR-3 판정 대상** | `state`는 이름 붙은 JSON이다: `{ "site": "x", "text": 본문, "textIsCutOff": 잘림 여부, "hasPhotoOrVideo": 사진·영상 여부 }`. 본문 외의 정보(계정 이름·프로필 등)는 넣지 않는다. 읽을 글자가 없는 게시물은 보내지 않는다. | `usePlan.md` §3-2 |
| **FR-4 가리기 정책** | 정책은 코드가 정한다. 초기값: `scamSignal` ≥ 0.6이면 가리기("사기 의심"), 나머지 셋 중 하나라도 ≥ 0.8이면 가리기(해당 이유), 0.4 이상 ~ 기준 미만은 가리지 않고 "확인 필요" 라벨. 초기값은 FR-8 시험 결과로 바꿀 수 있도록 상수 한 곳에 둔다. | `usePlan.md` §3-4 |
| **FR-5 결과 저장** | 질문별 원래 확률(`noul`)을 캐시에 저장한다(원본: 24시간, 최대 800개). 기준값만 바꿀 때는 Jev를 다시 부르지 않는다. 질문 문구나 형식이 바뀌면 `RUBRIC_VERSION`을 올려 이전 캐시를 무효화한다. | 원본 `background.ts`, `shared.ts` |
| **FR-6 화면 표시** | 표시 방식은 가리기(기본)·흐리게·도장 중 하나다. 가림 막대에는 이유와 **"다시 보기"** 버튼이 있고, 다시 접을 수 있다. "괜찮은 글" 라벨은 설정으로 켜고 끈다. 자동으로 펼치거나 닫지 않는다. | 원본 `theme`, `showNotSlop` |
| **FR-7 설정 화면** | 한국어 설정 창: TypeSafe 키 입력과 연결 확인, 전체 켜기/끄기, 표시 방식, 신호 4개 각각 켜기/끄기, "괜찮은 글" 라벨, 판정 기록 지우기. 판정기 선택(GPTZero)과 질문 직접 편집 칸은 없앤다 (질문은 고정, 결정 D-5). | 원본 `popup.ts` |
| **FR-8 한국어 시험** | `scripts/`에 시험 스크립트를 둔다. 가상 한국어 게시물 30건(신호별 "예" 최소 5건, 정답 미리 표기)을 (한국어 질문 / 영어 질문) × (`jev-latest` / `jev-preview`)로 보내고, 질문별 정확도, 0.4~0.6 구간 비율, 지연(중앙값·최대), `usage.input_tokens`를 기록한다. 키는 환경변수 `TYPESAFE_API_KEY`로만 읽는다. | `usePlan.md` §4 |
| **FR-9 오류 안내** | 401/403(키 확인), 402(크레딧 부족), 429·529(잠시 후 재시도, 지수 백오프), 시간 초과, 연결 실패를 쉬운 한국어로 보여 준다. | 원본 `safeError` |
| **FR-10 정리** | GPTZero 관련 코드(`src/gptzero-*.ts`), `proxy/`, 관련 테스트·스크립트·문서를 제거한다. 매니페스트의 선택 권한은 `https://api.typesafe.ai/*`만 남긴다(대안 경로를 쓰기로 하면 `https://ai-gateway.vercel.sh/*` 추가). | `usePlan.md` §3-5 |

## 4. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| **NFR-1 개인정보** | TypeSafe로 보내는 것은 게시물 본문과 FR-3의 필드뿐이다. 개인정보 처리방침에 "게시물 본문이 TypeSafe로 전송됨"을 적는다. 시험·스크린샷에는 가상 게시물만 쓴다. |
| **NFR-2 키 보관** | 키는 `background`의 `chrome.storage.local`(신뢰 영역 전용)에만 둔다. 페이지 쪽 코드(`content.js`)에는 키가 없다. 확장 패키지에 키를 넣지 않는다. |
| **NFR-3 권한** | 사이트 권한은 `https://x.com/*`, `https://www.x.com/*`로 좁힌다. `<all_urls>` 같은 넓은 권한을 쓰지 않는다. |
| **NFR-4 웹스토어 정책** | 모든 코드는 패키지 안에 있다(외부 스크립트 불러오기 금지). 난독화하지 않는다(압축은 허용). |
| **NFR-5 화면 (AGENTS.md §4)** | 설정 창은 본문 20px 이상, 버튼 높이 56px 이상, 영어·외래어 없이 쓴다. 피드 안 라벨은 X 화면 배치를 깨지 않는 선에서 키우고, 가림 막대 글씨는 20px로 한다. 아이콘만 있는 버튼은 쓰지 않는다. |
| **NFR-6 라이선스** | `LICENSE`의 원작자 저작권 표시를 유지한다. 확장 이름은 원작과 다르게 한다 (가칭 "피드 지킴이"). |
| **NFR-7 품질** | `npm run check`(lint, 타입 검사, 테스트·커버리지, 빌드, 패키지 검사, 저장소 검사)가 통과한다. 정책 함수(FR-4)와 응답 해석(FR-2)에 단위 테스트가 있다. |

## 5. 수용 기준

- [ ] **AC-1** 로컬 로드한 확장을 TypeSafe 키로 연결하면 "연결됨"이 표시된다.
- [ ] **AC-2** X 피드를 스크롤하면 보이는 게시물마다 라벨이 붙고, FR-4 기준을 넘는 게시물은 이유와 함께 가려지며, "다시 보기"로 펼쳐진다.
- [ ] **AC-3** 개발자 도구 네트워크 탭에서 TypeSafe 요청 본문에 질문 4개와 FR-3의 필드만 들어 있다.
- [ ] **AC-4** 설정에서 기준값만 바꾸면 Jev 요청이 새로 나가지 않고 화면 표시만 바뀐다.
- [ ] **AC-5** 잘못된 키, 네트워크 끊김에서 한국어 오류 문구가 나온다.
- [ ] **AC-6** FR-8 시험 결과 표가 `reference/slop-detector/usePlan.md`(또는 별도 결과 파일)에 기록되고, 그 결과로 FR-4 기준값이 확정된다.
- [ ] **AC-7** `npm run check`가 통과한다.
- [ ] **AC-8** 팀원 PC 2대 이상에서 `npm run package` zip을 풀어 로컬 로드해 AC-1~AC-2가 재현된다.
- [ ] **AC-9 (선택)** 웹스토어 Private 항목으로 심사를 통과하고, 지정 테스터 계정에서만 설치된다.

| D-11 | 2026-10-18 | **신청서의 고르는 칸은 사용자가 직접 고른다.** 「본인·가족」「일반·상세·특정 증명서」처럼 사람마다 답이 다른 고르는 칸은 가리키지 않고, 신청서 화면에서는 "직접 골라 주세요"를 띄운다. 길잡이가 가리키는 고르는 칸은 서류 종류와 약관 동의(필수만)뿐이다. 이미 그 서류 화면인데 같은 이름의 메뉴 링크는 가리키지 않는다. 모든 사이트에서 같다 | 사용자 결정. 전자가족관계에서 간편인증 뒤 신청서의 옆 메뉴 「혼인관계증명서」를 가리켰고, 누르자 본인 확인이 풀렸다(신청서의 같은 이름 고르는 칸이 빠져 AI가 서류를 아직 안 골랐다고 봄). 규칙은 `src/lib/handoff.js`(확장·서버 공통) |
