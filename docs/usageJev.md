Jev는 길잡이에서 **딱 두 가지 일**에만 쓰이고, 둘 다 Railway 중계 서버를 거쳐 호출됩니다.

## Jev가 쓰이는 두 곳

| 언제 | 무엇을 묻나 | 한 번에 |
|---|---|---|
| ① 어르신이 서류를 **검색**할 때 (「찾기」) | 적은 말이 서류 목록 27개 중 어느 것인지 고르기 | 호출 1번(질문 1개) |
| ② 안내 중에 **화면이 열리거나 바뀔 때** | 지금 화면에서 다음에 누를 곳 고르기 + 지금이 어느 단계인지 | 호출 1번(질문 2개) |

그 밖에 Jev가 하는 일은 없습니다. 서류 이름을 지어내거나 대신 눌러 주는 일에도 쓰이지 않습니다.

## ②가 다시 호출되는 때 (화면 변화가 있을 때)

0.7초 동안 화면이 잠잠해진 뒤에 묻습니다. 아래 일이 있을 때입니다.

| 일 | 설명 |
|---|---|
| 안내를 처음 시작할 때, 쪽이 새로 열릴 때 | 화면이 열림 |
| 어르신이 **뭔가를 누른 뒤** 0.9초 | 누른 곳이 맞았는지, 다음 화면이 뭔지 |
| 칸에 쓰거나 선택이 **바뀐 뒤** | 체크·선택 변화 |
| 가리키던 버튼이 사라졌거나 창이 열리고 닫혔을 때 | 배너 회전 같은 변화는 제외 |
| 「다시 찾기」를 눌렀을 때 | 저장된 답을 건너뛰고 새로 물음 |

## 호출하지 않고 건너뛰는 경우

| 조건 | 이유 |
|---|---|
| **동의하기 전** | 서버로 아무것도 보내지 않음 |
| 로그인 방법을 고르는 화면, 회원/비회원 창 | 사용자가 직접 고르는 곳 (「직접 골라 주세요」) |
| 약관 화면에서 체크 안 된 「필수」가 있을 때 | 코드가 규칙으로 처리 |
| 인증 창(iframe)이 화면을 덮고 있을 때 | 안은 볼 수 없어서 고정 도움말만 |
| 접속 대기 화면, 접속 차단 화면 | 기다리는 화면 |
| **같은 화면, 같은 누른 기록** | 저장된 답을 30분 동안 다시 씀 (이때는 Jev를 안 부름) |
| 서버가 오류로 답한 직후 | 배너가 바뀔 때마다 다시 묻지 않음 (「다시 찾기」로 재시도) |
| 후보가 하나도 없을 때 | 물을 것이 없음 |

## 비용과 한도

- 호출 1번은 입력 약 2천 토큰이고 응답은 0.2~0.6초입니다.
- 서버가 지키는 한도는 **IP당 분당 30번, 하루 전체 5,000번**입니다. 하루 한도는 Jev를 부르기 **직전에만** 셉니다. 건너뛴 화면은 세지 않습니다.
- 서류 하나를 끝까지 안내받는 데 보통 5~15번 정도 호출합니다. 이것은 화면 수에서 어림한 숫자이고, 실제로 세어 본 값은 아닙니다.

## 알아 둘 점

- 서버가 AI를 못 부르면 서류 검색은 이 컴퓨터에서 **글자 맞추기**로 대신합니다. 다음 버튼 안내는 대신할 방법이 없어서 멈춥니다.
- 하루 5,000번을 채우면 그날은 안내가 멈춥니다. 지금 사용자는 팀 정도라 한참 여유가 있습니다.

실제로 오늘 몇 번 불렸는지 세어 보고 싶으시면 말씀해 주세요. 서버는 요청 내용을 저장하지 않지만 호출 횟수는 Railway 로그의 `POST /v1/guide/next` 줄 수로 셀 수 있습니다. 그렇게 확인하는 것은 업데이트가 아니라 읽기라서 해도 됩니다.
